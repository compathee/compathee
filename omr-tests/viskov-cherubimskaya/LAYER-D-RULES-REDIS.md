# Layer D+: правила на лету + память Redis

## Правила нотной грамоты (hard / soft)

Срабатывают **на каждую гипотезу** Audiveris (head/pitch), зная текущие `fifths` + `mode`.

### Hard (всегда принудительно)
- При ♭ у ступени в ключе **запрещён ♯ на той же букве** (пример: си♭ при ключе → **не бывает си♯**; правка → си♭ или до).
- При ♯ у ступени в ключе **запрещён ♭ на той же букве** (фа♯ → не фа♭).
- Редкие двойные альтерации → review / snap.
- Частые энгармонические абсурды (E♯ при ≥2♭, C♭ при ≥2♯).

### Soft (тональность)
- Диатоника ключа + бекар (alter=0) разрешены.
- В миноре: вводный тон (g-moll → **F♯**), иногда VI↑.
- Иначе → snap к ближайшему разрешённому alter.

Демо: `tonal_rules_onthefly.py` → `tonal-rules-onthefly-demo.json`.

## Память Redis (умнее при следующих запусках)

Уже есть `compath_redis` в WP-22 — использовать его.

| Key | Value |
| --- | --- |
| `omr:grammar:v1:rules` | версия статических правил |
| `omr:mem:v1:{tenant}:{fp}:{ctx}` | `{alter, step, hits, last_ts, source}` |
| `omr:mem:v1:global:{fp}:{ctx}` | опционально агрегаты без ПДн |

`ctx = fifths|mode|step|shape|staff`  
`fp` = отпечаток страницы/пьесы  

### Цикл
1. Audiveris выдаёт гипотезу.
2. Hard rules → правка сразу.
3. Redis GET hint → soft prefer.
4. Voice Leader подтвердил → Redis INCR/SET (TTL ~180d).
5. Следующий прогон той же пьесы/контекста — меньше CPU на споры, меньше ложных диезов.

**Память не перекрывает hard-правила.**

## Ресурсы / токены
- Rules + Redis GET/SET: микросекунды–мс, RAM минимальна.
- LLM tokens: **0** (грамматика кодом; LLM только для спорных модуляций — опционально).

## Связь
WP-19 (правка), WP-22 (`compath_redis`, worker), WP-25 (прогоны).
