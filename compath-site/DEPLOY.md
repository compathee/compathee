# Deploy compath.ee

The assistant uploads the built site. Do not let the GitHub Action run until the FTP secrets exist, and do not treat the action as the whole cutover. The live web root is `/public_html`. It still serves the Sitebuilder site: an `index.php` of about 85 bytes wins over `index.html` while the host `DirectoryIndex` lists PHP first, and `Services/`, `Contacts/`, `et/` and `ru/` have their own Sitebuilder entry points.

The action uploads an allow-list and never deletes remote files (`dangerous-clean-slate: false`). It does not upload `api/` or replace `.htaccess`.

## What to back up

From the account that owns the site, before changing anything:

```bash
cd /public_html
tar -czf "$HOME/compath-public_html-$(date +%Y%m%d).tar.gz" .
cp -a .htaccess "$HOME/compath-htaccess-$(date +%Y%m%d).bak"
```

Keep that archive until the new site has been checked in a browser. It is the rollback.

## Files the action uploads

Every file under `compath-site/dist/` except `htaccess.snippet` maps to `/public_html/<same relative path>`. The exact list is `FTP-PATHS.txt`, regenerated by `node build.mjs`.

Uploaded by hand, once, and then left in place (the action never touches this folder):

- `/public_html/api/contact.php`
- `/public_html/api/.htaccess`
- `/public_html/api/config.php` created on the server from `api/config.example.php`

Do not upload `api/contact-test.php` or `api/config.example.php`.

## Cutover order

1. Build locally with `node compath-site/build.mjs` and take the backup above.
2. Upload `dist/` to `/public_html` (or run the manual GitHub Action after the secrets exist). Old `index.php` still wins, so the Sitebuilder site stays up during the upload.
3. Move the Sitebuilder directories out of the URL space. On this host, directory names are case-sensitive, so `Services` is not `services`.

```text
/public_html/Services          -> /public_html/_sitebuilder_backup/Services
/public_html/Contacts          -> /public_html/_sitebuilder_backup/Contacts
/public_html/et/Services       -> /public_html/_sitebuilder_backup/et-Services
/public_html/et/Contacts       -> /public_html/_sitebuilder_backup/et-Contacts
/public_html/ru/Services       -> /public_html/_sitebuilder_backup/ru-Services
/public_html/ru/Contacts       -> /public_html/_sitebuilder_backup/ru-Contacts
```

4. Rename every Sitebuilder front controller so it cannot beat `index.html`:

```text
/public_html/index.php         -> /public_html/index.php.sitebuilder.bak
/public_html/et/index.php      -> /public_html/et/index.php.sitebuilder.bak
/public_html/ru/index.php      -> /public_html/ru/index.php.sitebuilder.bak
```

If an `index.php` also exists in a language subfolder we now use (`et/teenused`, `contact`, and so on), rename that file the same way. Leave `css/`, `js/`, `gallery/` and `gallery_gen/` where they are. They are unused, and deleting them is not required for the new site to show.

5. Merge `.htaccess`. Download the live file (it is about 1657 bytes and is not readable from the web). Keep every hosting PHP line already in it: `AddHandler`, `AddType`, `suPHP_ConfigPath`, `php_flag`, `php_value`, and any SSL or auth block. Paste `htaccess.snippet` after those lines. If `RewriteEngine On` is already there, paste the `RewriteRule` lines only once.

The snippet sets `DirectoryIndex index.html index.php`, turns indexes off, 301-redirects the old Sitebuilder URLs, and points unknown paths at `/404.html`.

Old URLs and where they go:

| Old URL | New URL |
|---|---|
| `/Services/` and anything under it | `/services/` |
| `/Contacts/` and anything under it | `/contact/` |
| `/et/Services/` and anything under it | `/et/teenused/` |
| `/et/Contacts/` and anything under it | `/et/kontakt/` |
| `/ru/Services/` and anything under it | `/ru/uslugi/` |
| `/ru/Contacts/` and anything under it | `/ru/kontakty/` |

`/et/` and `/ru/` stay. They are the Estonian and Russian home pages. The old Services page was a single URL, so translations and video do not have their own redirects. That page now opens the new services overview.

6. Upload the contact handler and create `api/config.php` on the server. Fill `smtp_pass`. The example assumes SMTP `compath.ee:465` with user `compath@compath.ee`, From `support@compath.ee`, and the only recipient `support@compath.ee`. Confirm the mailbox may send as that From address. Make `api/` writable by PHP so it can create `api/contact-rate/` (mode 0700) and `api/contact-mail.log`. The script refuses to create that store anywhere else.
7. Check `https://compath.ee/health.txt` contains `deploy OK`, then open `/`, `/et/`, `/ru/`, `/contact/` and one old URL such as `/Services/`.

## Rollback

Restore the archive from step 1, or, if only the cutover changed:

1. Put the saved `.htaccess` back.
2. Rename `index.php.sitebuilder.bak` to `index.php` at the root, in `et/`, and in `ru/`.
3. Move `_sitebuilder_backup/*` back to `Services/`, `Contacts/`, and the language subfolders.

The new HTML can stay on disk during rollback. With `index.php` restored and the old `DirectoryIndex`, Sitebuilder is what visitors get.

## Secrets for the GitHub Action

| Secret | Value |
|---|---|
| `COMPATH_FTP_SERVER` | FTP host |
| `COMPATH_FTP_USERNAME` | FTP user |
| `COMPATH_FTP_PASSWORD` | FTP password |
| `COMPATH_FTP_REMOTE_DIR` | `/public_html/` |

The workflow file is `.github/workflows/deploy-compath-site.yml`. It runs only from `workflow_dispatch`.

## Preview at /preview-2026/

The owner can review the new site before the cutover. Build it with `node compath-site/build.mjs --preview`. Upload every file in `PREVIEW-FTP-PATHS.txt` to `/public_html/preview-2026/`, including `.htaccess`. Do not merge that file into `/public_html/.htaccess`.

The preview `.htaccess` applies only inside that folder. It sets `DirectoryIndex index.html`, turns indexes off, and sends `X-Robots-Tag: noindex, nofollow`. It has no rewrite rules. The Sitebuilder site at `/` stays as it is.

Open `https://compath.ee/preview-2026/`, `/preview-2026/et/` and `/preview-2026/ru/`. `health.txt` in that folder says `preview OK`. The contact form is not on these pages. Removing the preview later is deleting `/public_html/preview-2026/` only.

The manual workflow `.github/workflows/deploy-compath-preview.yml` uploads `dist-preview/` to `${COMPATH_FTP_REMOTE_DIR}preview-2026/`. `COMPATH_FTP_REMOTE_DIR` must end with a slash (`/public_html/`). It never deletes remote files and does not upload the production site.
