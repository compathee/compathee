**Date:** 2026-10-12  
**Status:** Product memo — **не юридическое заключение**. Перед публикацией Partner/Pro+AI и ToS — ревью юристом (EE/EU).

## 0. Позиционирование продукта (маркетинг ↔ право)

**Разрешённый narrative для shop / Partner / Pro+AI:**

> Compath OMR — инструмент **реставрации и восстановления** уникальных нотных копий (рукописи, архивные сканы, экземпляры без типографской/цифровой редакции), по духу близкий к реставрации старых фильмов и аудиозаписей: сохранить хрупкий носитель в современном пригодном для работы виде (MusicXML, разучивание, опционально синтез для практики).

**Целевые сценарии (зелёные для позиционирования):**

* церковные/хоровые архивы, личные рукописи регента;  
* PD / истекший срок охраны произведения;  
* материалы, на которые у хора/архива есть письменное разрешение;  
* собственные сочинения и заказы хора.

**Нельзя подменять этим narrative:**

* «реставрация» коммерческого PDF современного издателя без лицензии;  
* публичный каталог «восстановленных» чужих партитур на стороне Compath;  
* обещание, что restore = свободные права на произведение.

В ToS и на странице Copyright: *technical restoration service ≠ clearance of copyright*. Warranty клиента обязателен (см. §5, §11).

## 1. Что вообще охраняется

На «PDF с нотами» обычно несколько слоёв:

| Слой | Что это | Типичный срок (EU, ориентир) |
|---|---|---|
| **Музыкальное произведение** | мелодия, гармония, текст | жизнь автора + 70 лет |
| **Редакция / нотный набор** | конкретная вёрстка, пальцы, редакторские указания | отдельное право издания/редакции (зависит от юрисдикции и договора) |
| **Графический файл / скан** | PDF, фото страниц | права на воспроизведение экземпляра |
| **Производные** | MusicXML, MIDI, синтез аудио из нот | использование того же произведения (+ иногда редакции) |

**Вывод:** OMR и «PDF → аудио» — не «просто формат», а **обработка охраняемого контента** (и часто создание производной формы). Конвертация **не даёт** прав на произведение и **не снимает** запрет на публикацию/продажу чужих нот.

## 2. Три операции Compath — правовой смысл

| Операция | Технически | По правам (продуктово) |
|---|---|---|
| **Читка / OMR** | PDF/скан → MusicXML | Воспроизведение + преобразование в машиночитаемую форму |
| **Коррекция / grammar** | правка высот, ключей | Та же производная; результат всё ещё чужое произведение (если не PD) |
| **Конвертация в аудио** | MusicXML/MIDI → синтез | Публичное исполнение / доведение до сведения в зависимости от UX (локально у хора vs раздача файла) |

Синтез «как метроном/практика» **не** равен лицензии на фонограмму артиста, но **не освобождает** от прав на само произведение.

## 3. Когда можно (продуктовые зелёные зоны)

Клиент (хор / Partner) должен иметь **хотя бы одно** основание, например:

1. **Public domain** — срок охраны истёк; осторожно с современной редакцией/набором.  
2. **Собственные / заказанные** ноты (хор — правообладатель или есть письменное разрешение).  
3. **Лицензия издателя** на rehearsal use (часто: показ участникам хора, без публичной перепродажи файла).  
4. **Законные исключения** (учебные и т.п.) — **узкие**, в EE/EU не стоит на них строить коммерческий API без юриста.

Красные зоны без отдельного договора с правообладателем:

- Загрузка коммерческого PDF издателя «чтобы раздать MusicXML/MP3 всем в интернете».  
- Публичный каталог чужих распознанных партитур на стороне Compath.  
- Продажа «готовых» чужих произведений как контента Compath.

## 4. Модель ответственности Compath (как у зрелых OMR API)

Ориентир рынка (Flat OMR, SheetMusicConverter и аналоги):

- Сервис = **технический процессор** по поручению клиента.  
- Клиент **гарантирует** права на загружаемый материал и на запрошенные действия (OMR, хранение, playback, экспорт).  
- Compath **не** становится издателем и **не** публикует чужие партитуры.  
- Короткий retention файлов (уже в WP-22: часы, не вечный архив).  
- Indemnity + возможность блокировки/удаления по жалобе правообладателя.

Уже в ТЗ WP-22: *«Партнёр подтверждает права на загружаемые партитуры (ToS); Compath не становится издателем и не публикует чужие ноты.»* — это базовая линия; её нужно развернуть в ToS/DPA.

## 5. Что должно быть в ToS / UI (MUST перед продажей)

1. **Чекбокс / warranty** при upload и при Partner job: «Имею права или разрешение на обработку этого материала, включая распознавание и (если включено) синтез аудио».  
2. **Запрет** использовать сервис для пиратского распространения.  
3. **Индемнити** клиента в пользу Compath OU.  
4. **Notice-and-takedown** процедура (контакт для правообладателей, срок реакции).  
5. **Retention** исходников/артефактов — короткий; обучение (§10 design) — на **подтверждённых** правках, tenant-first; global skills — без хранения полных охраняемых партитур (только анонимные ctx/фичи).  
6. **Разделение UX:**  
   - локальный/закрытый rehearsal playback для участников хора ≠  
   - публичная выкладка MP3/MusicXML.  
7. Отдельный договор для **издателей** (on-prem / private endpoint — WP-22 COULD).

## 6. Обучение на правках и авторское право

| Можно (осторожно) | Нельзя без базы |
|---|---|
| Skills: «в таком ctx alter=X» после VL confirm | Класть полные MusicXML чужих изданий в публичный/global dataset |
| Синтетические / PD примеры для тестов (как Viskov — проверить статус!) | Обучать внешнюю LLM на загруженных партитурах клиентов без договора |

Тестовый материал «А. Висков — Херувимская» для внутренних прогонов: **проверить статус охраны** (дата смерти автора, редакция PDF) до любого публичного демо/магазина.

## 7. Аудио отдельно от «читки»

Даже при легальном OMR для хора:

- **MusicXML внутри плагина** для разучивания — обычно покрывается warranty клиента + закрытый контур.  
- **Экспорт MP3/MIDI наружу** — выше риск; в UI явно предупреждать; для Partner API — отдельный scope/флаг `audio_export` и тот же warranty.  
- Не обещать «лицензию на произведение» вместе с подпиской Pro+AI / OMR API — продаём **технологию**, не права на репертуар.

## 9. Краткие ответы на частые вопросы

**«Мы только распознаём — это же не копирование?»**  
Распознавание создаёт копию/производную в другом формате. Нужны права или законное основание у клиента.

**«Аудио из MIDI — это уже наше?»**  
Синтез файла может принадлежать вам как фонограмме синтеза, но **права на произведение** остаются у автора/издателя. Без их разрешения нельзя свободно распространять.

**«Хор купил бумажные ноты — можно в облако?»**  
Часто да для внутреннего разучивания, **если** лицензия издания это допускает; не всегда можно делать общий MusicXML/MP3 «для интернета». Warranty клиента + по возможности ссылка на условия издания.

**«Public domain ноты из IMSLP?»**  
Часто да для произведения; проверить, что конкретный PDF не под современной редакцией с отдельной охраной.

## 10. Эстонское право (AutÕS / VÕS / DSM) — выводы для Compath

Источник для проработки: методическое руководство по реформе авторских договоров в EE  
(AutÕS, VÕS, Директива ЕС 2019/790 DSM) — NotebookLM artifact, 2026-10-12.

### 10.1 Что важно для нашего продукта

| Норма / институт | Смысл | Как касается Compath |
|---|---|---|
| **AutÕS** + **DSM art. 18–23** | Вознаграждение авторов, прозрачность, расторжение | Если Compath **заказывает** музыку, аранжировки, тексты, методички у физлиц — нужны авторские договоры и (где применимо) отчётность |
| **Kohane ja proportsionaalne tasu** (AutÕS § 14 / DSM art. 18) | Соответствующее и пропорциональное вознаграждение | При лицензиях **от авторов** на контент (не на софт) |
| **Teavitamiskohustus** (AutÕS § 49¹) | ≥1×/год письменно: способы использования, доход, вознаграждение | Обязанность **пользователя произведения** перед автором; заложить в шаблон договора с авторами |
| **Bestseller / AutÕS § 49²** | Доплата, если вознаграждение несоразмерно доходу | Императивно; нельзя отказом в договоре «закрыть» |
| **Неиспользование / AutÕS § 49³** | Отказ/расторжение, если произведение не используют (ориентир 2 года, max 5) | Учитывать в эксклюзивных лицензиях на контент |
| **Императивность §§ 49²–49⁴** | Ограничения прав автора ничтожны | Шаблоны договоров не должны «выключать» эти права |
| **Изъятия (DSM / AutÕS)** | **Компьютерные программы**; бесплатные публичные лицензии (CC); договоры с **конечными пользователями** произведения | Код плагина/API — как ПО, под другим режимом; EULA с хором ≠ авторский договор с композитором |
| **Piraatkoopia (AutÕS § 80¹)** | Незаконная копия | ToS/AUP: запрет загружать/распространять пиратские ноты; takedown |
| **Andmebaasi tegija (AutÕS § 75³)** | Право изготовителя БД при существенной инвестиции | Redis skills / каталоги метаданных — не складывать охраняемые полные партитуры в «общую БД» без правовой базы; анонимные ctx OK |
| **Автор через OÜ/FIE** | Защита автора vs стороны по VÕS | В договорах с подрядчиками явно фиксировать статус автора/правопреемника |

### 10.2 Чего Compath обычно **не** делает (и не должен)

- Не становится издателем чужого репертуара.  
- Не продаёт «права на произведение» вместе с Pro/OMR.  
- Не строит публичный каталог распознанных чужих партитур.

### 10.3 Когда нормы об авторских договорах **включаются** у нас

1. Заказ нот/аранжировок/переводов у автора → **авторский договор** (+ teavitamine, если мы пользователь произведения).  
2. Лицензия от издателя на demo/seed-репертуар → лицензионный договор (простая/исключительная — AutÕS § 48¹).  
3. ПО плагина и API → режим **программ** (изъятие из части DSM-защит авторов контента); нужны EULA + IP assignment сотрудников/подрядчиков на код.
